Why OXIS

Everything around your shell,
in one fast window.

Keep every command and alias you have. OXIS adds the pieces you normally juggle across five apps — and makes all of it scriptable.

Your shell, unchanged

OXIS starts a real shell in a real pseudo-terminal: PowerShell 7 or Windows PowerShell on Windows, your $SHELL on Linux. Anything that doesn't start with ' goes straight to it — in full colour (16, 256 and 24-bit), with prompts, REPLs and interactive tools included.

pwsh 7Windows PowerShellbashzshfishOXIS_SHELL=…

50+ built-in 'commands

Start a line with an apostrophe and OXIS takes it: open files, switch themes, run tasks, manage plugins — with history, reverse search and readline keys in one prompt that sits on every screen.

'edit'theme'task'workflow'workspace'market'plugin'update'version'backup

A real editor, built in

Syntax highlighting, tabs, a file tree, find & replace, Vim-style Normal/Insert/Visual modes and live HTML/Markdown preview. 'edit src/app.ts and you're in — no context switch.

Workspaces that remember

Each project keeps its own tasks, workflows, plugins and documents, linked to the real folder and its git remote. Switch projects with one command.

▸ install
▸ build
▸ test

Command palette

Ctrl+Shift+P finds any command, plugin shortcut or task as you type.

Plugins with permissions

Lua plugins declare what they touch — fs, net, shell… — and can never get more. Each runs in its own VM, so a bad plugin can't take your session down.

Updates itself — safely

'update install builds the latest source (or grabs the CI binary), swaps it in, and rolls back if the new build doesn't start. 'version shows exactly which commit you run.

Private by default

No account and no telemetry. Password prompts are masked, and the only network calls are the ones you can see: update checks against GitHub (one setting turns them off), the Market, and what your plugins declare.

Desktop app — or a browser tab

A native window on Windows and Linux (Go + WebView), and the same UI at http://127.0.0.1:1420 while it runs. Everything ships as one ~14 MB binary.

Scriptable to the core

Your terminal is
a Lua program.

Commands, tasks, workflows, keymaps, events and the home screen are all plain Lua — in a plugin, a project's workspace.lua or your ~/.oxis/config.lua. Save, and it reloads.

Install

Up and running in a minute.

Every push to main is built by GitHub Actions and published to the rolling latest-build release.

Windows 10 & 11 (x64)

Use the installer, or the portable oxis.exe. WebView2 already ships with Windows.

Installer (.msi) Portable .exe
  1. Run the installer (or the .exe — it keeps its data next to itself).
  2. Type 'help, or just start typing commands you already know.
  3. 'update install keeps you on the newest build from then on.
PowerShell
PS> Invoke-WebRequest https://github.com/oxlaboratory/oxis/releases/download/latest-build/oxis.exe -OutFile oxis.exe
PS> .\oxis.exe

Linux (x64)

A .deb for Debian and Ubuntu, a portable tarball, or the bare binary. OXIS needs GTK 3 and WebKitGTK — the .deb pulls them in.

.deb package Portable .tar.gz
  1. Install the package (or run the binary after installing libgtk-3-0 and libwebkit2gtk-4.1-0).
  2. OXIS opens your $SHELL — bash, zsh or fish.
bash
$ curl -LO https://github.com/oxlaboratory/oxis/releases/download/latest-build/oxis_1.2.1_amd64.deb
$ sudo apt install ./oxis_1.2.1_amd64.deb
$ oxis

Build it yourself

Go 1.22+ and Node.js 24+; on Linux also libgtk-3-dev libwebkit2gtk-4.1-dev pkg-config. macOS isn't tested yet, but Wails supports it.

  1. npm run setup checks your tools and installs dependencies.
  2. npm run build stamps the version, commit and build number into the binary.
  3. npm run dev rebuilds and relaunches on every change.
terminal
$ git clone https://github.com/oxlaboratory/oxis.git
$ cd oxis
$ npm run setup
$ npm run build   # → dist/oxis.exe or dist/oxis
Questions

Switching? Good questions.

Do I have to change shells or relearn anything?
No. OXIS runs the shell you already use — PowerShell 7 (or Windows PowerShell) on Windows and your $SHELL on Linux, including zsh and fish; set OXIS_SHELL to pick another. Your profile, aliases and prompt load as usual, and anything not starting with ' goes straight to the shell.
Does OXIS collect any data?
No telemetry and no account. OXIS only goes online to check GitHub for updates ('config set updateCheckOnStartup false turns that off), to browse the Market, and for requests your plugins make — which need the net permission.
Is it free?
Yes. OXIS is open source under the Apache License 2.0, and free Market plugins stay free. Premium plugins are planned as optional monthly subscriptions; none can be bought yet.
How do updates work — and how do I know what I'm running?
'update compares your build's commit with main on GitHub and says how many commits behind you are. 'update install builds the latest source (falling back to the prebuilt binary), swaps it in and restores the old one if the new build fails to start. 'version shows the version, build number, commit, release tag, channel and build date — 'version --copy puts it on your clipboard for a bug report.
Can I bring my setup with me?
Your shell profile works as-is. On top of that, ~/.oxis/config.lua runs at startup, themes are JSON files in ~/.oxis/themes/, each project can carry a .oxis/workspace.lua, and 'backup / 'restore move everything between machines.
What about macOS?
There's no macOS build yet. OXIS is built on Wails, which supports macOS, so building from source should work — it just isn't tested. Issues and pull requests are welcome.
