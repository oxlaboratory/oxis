What it is

Not a terminal emulator.
A workspace around your shell.

OXIS starts your actual shell in a real pseudo-console and leaves it alone. Around it, it puts the things you would otherwise juggle across several apps — and makes each of them scriptable.

01 · REAL SHELLS

Your shell, unchanged

Your profile, aliases and prompt load as usual. Anything that doesn't start with ' goes straight to the shell — REPLs, prompts and full-screen programs like vim and htop included. Pick a different shell per tab.

02 · WORKSPACES

One per project

A workspace links to the project's folder and its own Git remote, and carries its tasks, workflows and plugins. Home shows its state at a glance: branch, changes, tasks and what to do next.

'workspace init'task test'workflow check
03 · LUA

Programmable throughout

Commands, workflows, keymaps, events and Home panels are plain Lua 5.4 — in a plugin, a project's workspace.lua or your config.lua. Save, and it reloads. Plugins declare their permissions.

oxis.commandoxis.workflowoxis.askoxis.every
Home

The project at a glance.

Home is the workspace's start page: its folder, Git remote and plugins; the tasks you run most, one click each; and the project's Git state, today's activity and recent files beside them.

  • Next up suggests what needs you — uncommitted changes, unpushed commits, a command that just failed
  • Start lists the commands and shortcuts that matter on day one
  • Plugins can add their own header and shortcuts with oxis.dashboard
Terminal

Tabs, splits and one prompt.

Every tab and split pane is its own shell, opened in the folder you're working in. One prompt at the bottom sends to the focused pane, with history, reverse search and completion in any shell.

  • Tab completes files, Git branches, npm run scripts, SSH hosts and make targets; history suggests the rest
  • Ctrl+Shift+Space labels every URL, path and hash on screen — type the letter to copy
  • Fold, re-run or copy any command's output; 'broadcast types into every pane at once
  • Hyperlinks, clipboard and progress from the tools that send them (OSC 8, 52, 9;4)
Editor

An editor beside your shell.

'edit opens any file next to the prompt, with a file tree, tabs and a minimap. Mistakes are underlined as you type, names are suggested, and HTML and Markdown get a live preview.

  • Ctrl+P to any file, search in files, find & replace, go to symbol
  • Vim's Normal, Insert and Visual modes — or turn them off
  • Click src/app.ts:12:5 in a compiler error to open it right there
Commands

Everything is a command.

Start a line with an apostrophe and OXIS takes it: more than 60 built-in commands for files, themes, tasks, workflows, plugins and workspaces. Ctrl+Shift+P finds any of them as you type.

  • The palette also searches plugin commands, tasks and your history
  • Ctrl+, opens Settings: every setting, grouped and searchable
  • 'update install swaps in the newest build and rolls back if it doesn't start
In the box

Everything ships in one binary.

About 14 MB, no runtime to install. A native window on Windows and Linux (Go and WebView), and the same interface in a browser tab while it runs.

Per-tab shells

PowerShell, Git Bash, WSL or cmd on Windows; your $SHELL on Linux. 'shell gitbash opens a tab with another.

Session restore

Tabs, splits, folders, recent output and unsaved editor text come back after a restart.

Workspaces

Per-project folder, Git remote, tasks, workflows and plugins; detects Node, Go, Rust and Python projects and suggests tasks.

Workflows

Steps with retries, conditions, environment and parallel runs, failing on real exit codes.

Lua plugins

Real Lua 5.4 with LuaRocks and C modules, each plugin in its own VM with declared permissions.

Plugin Market

'market install from the terminal; 'plugin publish files yours for review.

Built-in editor

Live problems, suggestions, search, minimap, Vim modes and a Markdown and HTML preview.

Quick select & images

Copy anything on screen with two keys; 'imgcat shows pictures in the output.

Recording & triggers

'record saves a tab as an asciinema cast; 'trigger highlights the lines that matter, with a sound or notification.

Summon key

Win+` brings OXIS to the front from anywhere; Open in OXIS on folders in Explorer.

Self-updating

'update install installs the newest build; 'version shows the exact commit and build.

Private by default

No account and no telemetry. Network use is visible: update checks, the Market, and what plugins declare.

Install

Up and running in a minute.

Every push to main is built by GitHub Actions and published to the rolling latest-build release.

Windows 10 & 11 (x64)

Use the installer, or the portable oxis.exe. WebView2 already ships with Windows.

Installer (.msi) Portable .exe
  1. Run the installer (or the .exe — it keeps its data next to itself).
  2. Type 'help, or just start typing commands you already know.
  3. 'update install keeps you on the newest build from then on.
PowerShell
PS> Invoke-WebRequest https://github.com/oxlaboratory/oxis/releases/download/latest-build/oxis.exe -OutFile oxis.exe
PS> .\oxis.exe

Linux (x64)

A .deb for Debian and Ubuntu, a portable tarball, or the bare binary. OXIS needs GTK 3 and WebKitGTK — the .deb pulls them in.

.deb package Portable .tar.gz
  1. Install the package (or run the binary after installing libgtk-3-0 and libwebkit2gtk-4.1-0).
  2. OXIS opens your $SHELL — bash, zsh or fish.
bash
$ curl -LO https://github.com/oxlaboratory/oxis/releases/download/latest-build/oxis_1.2.1_amd64.deb
$ sudo apt install ./oxis_1.2.1_amd64.deb
$ oxis

macOS (Apple silicon) — preview

OXIS.app, zipped. It's built and tested on macOS with every change, but hasn't been tried on a Mac by a person yet — tell us how it goes.

OXIS.app (.zip)
  1. Unzip and move OXIS.app to Applications.
  2. It isn't signed yet: the first time, right-click it → Open.
  3. OXIS opens your $SHELL — zsh by default.
zsh
% unzip oxis-*-macos-arm64.zip -d /Applications
% xattr -dr com.apple.quarantine /Applications/OXIS.app
% open /Applications/OXIS.app

Build it yourself

Go 1.22+ and Node.js 24+; on Linux also libgtk-3-dev libwebkit2gtk-4.1-dev pkg-config. On macOS, Xcode's command line tools.

  1. npm run setup checks your tools and installs dependencies.
  2. npm run build stamps the version, commit and build number into the binary.
  3. npm run dev rebuilds and relaunches on every change.
terminal
$ git clone https://github.com/oxlaboratory/oxis.git
$ cd oxis
$ npm run setup
$ npm run build   # → dist/oxis.exe or dist/oxis
Questions

Good questions.

What is OXIS, exactly?
A development workspace that runs your real shell — not an imitation of one — with tabs and split panes, a built-in editor, per-project workspaces, tasks, workflows and Lua plugins around it. Every part can be changed: themes, keymaps, commands and the Home screen.
Do I have to change shells or relearn anything?
No. OXIS runs the shell you already use — PowerShell 7 (or Windows PowerShell) on Windows and your $SHELL on Linux, including zsh and fish; 'shell <name> opens a tab with another, and OXIS_SHELL changes the default. Your profile, aliases and prompt load as usual, and anything not starting with ' goes straight to the shell.
Does OXIS collect any data?
No telemetry and no account. OXIS only goes online to check GitHub for updates ('config set updateCheckOnStartup false turns that off), to browse the Market, and for requests your plugins make — which need the net permission. 'update install counts itself in the public download total once a day ('config set countInstalls false turns that off).
Is it free?
Yes. OXIS is open source under the Apache License 2.0, and free Market plugins stay free. Premium plugins are planned as optional monthly subscriptions; none can be bought yet.
How do updates work — and how do I know what I'm running?
'update compares your build with main on GitHub; a new tab tells you when you're behind. 'update install fetches the latest build, swaps it in and restores the old one if the new one fails to start. 'version shows the version, build number, commit, release tag, channel and build date.
Can I bring my setup with me?
Your shell profile works as-is. On top of that, ~/.oxis/config.lua runs at startup, themes are JSON files in ~/.oxis/themes/, each project can carry a .oxis/workspace.lua, and 'backup / 'restore move everything between machines.
What about macOS?
There's a preview for Apple silicon: OXIS.app in the latest build. Every change is built on macOS by CI, but it hasn't been used on a Mac by a person yet, so issues and pull requests are very welcome. It isn't signed: right-click → Open the first time.
