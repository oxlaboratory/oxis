01 · Automate projects

Your project runs itself.

A workspace is linked to the project's real folder and its own git repository, so two projects never share a remote. Tasks run in that folder, watchers react to saves, and monitors keep an eye on what's running.

  • 'task test runs the project's tests; 'autotest runs them on every save
  • 'healthcheck https://… every 30 watches a service and says when it changes
  • 'mon, 'top and 'watch-mem show the machine live — Ctrl+C stops them
  • Tab completes files, git branches, npm run scripts, SSH hosts and make targets in PowerShell, bash or cmd, and history suggests the rest as you type
  • Click src/app.ts:12:5 in a compiler error to open the editor right there
  • PowerShell, Git Bash, WSL or cmd, tab by tab: 'shell gitbash
  • Fold, re-run or copy any command's output; rename, duplicate and drag tabs
  • Ctrl+Shift+Space puts a letter on every URL, path and hash on screen — type it to copy, no mouse
  • 'broadcast types into every pane at once; 'record saves a tab as an asciinema cast; 'imgcat shows an image right in the output
  • A Settings window (Ctrl+,), and sound effects you can swap for your own
  • Speaks modern terminal: hyperlinks, clipboard and progress from the tools that send them (OSC 8, 52, 9;4)
  • Win+` brings OXIS to the front from any program; Open in OXIS on any folder in Explorer
  • Right-click the file tree to create, rename, duplicate or delete
02 · Edit documents

An editor where you work.

'edit opens any file beside your shell. Mistakes are underlined as you type, names are suggested, and Ctrl+P jumps to any file. HTML and Markdown get a live preview that loads your own stylesheets.

  • Search in files, find & replace, a minimap and VS Code's editing keys
  • Vim's Normal, Insert and Visual modes — counts, registers, dd, cw, / — or turn them off
  • Notes, TODOs and snippets for the project, from the prompt: 'note, 'todo, 'snip
  • Pictures open in an image viewer, not as bytes
03 · Build workflows

Program the workspace.

Commands, workflows, keymaps and events are plain Lua — in a plugin, a project's workspace.lua or your config.lua. Save, and it reloads. Plugins can ask questions, run on timers, animate a line and stream a program's output.

  • Real Lua 5.4 inside OXIS: about 7× faster than before, LuaRocks packages and C modules load, and a busy plugin never freezes the window
  • oxis.workflow: steps with retries, conditions, env and parallel runs
  • oxis.ask holds a conversation in the prompt; oxis.line redraws in place
  • Each plugin declares its permissions — fs, net, shell — and can't get more; the first use asks in the prompt
  • 'plugin publish sends yours to the Market
04 · Customize everything

Nothing is fixed.

Every colour, font, glow and gradient is a theme setting you can change live. The prompt label, the status bar, the Home screen and its commands, your keymaps — all yours to change.

  • 'theme edit: all 85 settings with a live preview
  • The sky on Home: sun only, moon only, how many clouds and stars — or your own pixel art
  • Keymaps, Home shortcuts and new commands from config.lua
  • 'backup and 'restore take it all to another machine

Real, not emulated

Your real shell, files and tools.
Nothing pretends.

OXIS starts your actual shell in a real pseudo-console, reads and writes your actual files, and runs your actual programs. It adds the pieces you'd otherwise juggle across five apps — and makes all of them programmable.

Your shell, unchanged

PowerShell 7 or Windows PowerShell on Windows, your $SHELL on Linux. Anything that doesn't start with ' goes straight to it — in full colour, with prompts, REPLs and full-screen programs. Tabs and split panes put a dev server beside your work, and they come back after a restart.

50+ built-in 'commands

Start a line with an apostrophe and OXIS takes it: open files, switch themes, run tasks and workflows, manage plugins and workspaces — with history, reverse search and readline keys in one prompt.

'edit'task'workflow'workspace'theme'market'plugin'sysinfo'update'backup

Command palette

Ctrl+Shift+P finds any command, plugin shortcut or task as you type.

Updates itself — safely

'update install fetches the newest build, swaps it in, and rolls back if it doesn't start. A new tab says when you're behind; 'version shows the exact commit.

Private by default

No account, no telemetry. The only network calls are the ones you can see: update checks, the Market, and what your plugins declare.

Plugins that can't overreach

Each Lua plugin runs in its own VM and declares what it touches. A plugin can't take over OXIS's own commands, and one that fails can't take your session down with it.

Desktop app — or a browser tab

A native window on Windows, Linux and macOS (Go + WebView), and the same UI at http://127.0.0.1:1420 while it runs. One ~14 MB binary.

Install

Up and running in a minute.

Every push to main is built by GitHub Actions and published to the rolling latest-build release.

Windows 10 & 11 (x64)

Use the installer, or the portable oxis.exe. WebView2 already ships with Windows.

Installer (.msi) Portable .exe
  1. Run the installer (or the .exe — it keeps its data next to itself).
  2. Type 'help, or just start typing commands you already know.
  3. 'update install keeps you on the newest build from then on.
PowerShell
PS> Invoke-WebRequest https://github.com/oxlaboratory/oxis/releases/download/latest-build/oxis.exe -OutFile oxis.exe
PS> .\oxis.exe

Linux (x64)

A .deb for Debian and Ubuntu, a portable tarball, or the bare binary. OXIS needs GTK 3 and WebKitGTK — the .deb pulls them in.

.deb package Portable .tar.gz
  1. Install the package (or run the binary after installing libgtk-3-0 and libwebkit2gtk-4.1-0).
  2. OXIS opens your $SHELL — bash, zsh or fish.
bash
$ curl -LO https://github.com/oxlaboratory/oxis/releases/download/latest-build/oxis_1.2.1_amd64.deb
$ sudo apt install ./oxis_1.2.1_amd64.deb
$ oxis

macOS (Apple silicon) — preview

OXIS.app, zipped. It's built and tested on macOS with every change, but hasn't been tried on a Mac by a person yet — tell us how it goes.

OXIS.app (.zip)
  1. Unzip and move OXIS.app to Applications.
  2. It isn't signed yet: the first time, right-click it → Open.
  3. OXIS opens your $SHELL — zsh by default.
zsh
% unzip oxis-*-macos-arm64.zip -d /Applications
% xattr -dr com.apple.quarantine /Applications/OXIS.app
% open /Applications/OXIS.app

Build it yourself

Go 1.22+ and Node.js 24+; on Linux also libgtk-3-dev libwebkit2gtk-4.1-dev pkg-config. On macOS, Xcode's command line tools.

  1. npm run setup checks your tools and installs dependencies.
  2. npm run build stamps the version, commit and build number into the binary.
  3. npm run dev rebuilds and relaunches on every change.
terminal
$ git clone https://github.com/oxlaboratory/oxis.git
$ cd oxis
$ npm run setup
$ npm run build   # → dist/oxis.exe or dist/oxis
Questions

Switching? Good questions.

What is OXIS, exactly?
A programmable workspace for automating projects, editing documents and building workflows. It runs your real shell — not an imitation of one — beside a built-in editor, per-project workspaces, tasks, workflows and Lua plugins, and every part of it can be changed: themes, keymaps, commands, the Home screen, even the sky.
Do I have to change shells or relearn anything?
No. OXIS runs the shell you already use — PowerShell 7 (or Windows PowerShell) on Windows and your $SHELL on Linux, including zsh and fish; set OXIS_SHELL to pick another. Your profile, aliases and prompt load as usual, and anything not starting with ' goes straight to the shell.
Does OXIS collect any data?
No telemetry and no account. OXIS only goes online to check GitHub for updates ('config set updateCheckOnStartup false turns that off), to browse the Market, and for requests your plugins make — which need the net permission. 'update install counts itself in the public download total once a day ('config set countInstalls false turns that off).
Is it free?
Yes. OXIS is open source under the Apache License 2.0, and free Market plugins stay free. Premium plugins are planned as optional monthly subscriptions; none can be bought yet.
How do updates work — and how do I know what I'm running?
'update compares your build with main on GitHub; a new tab tells you when you're behind. 'update install fetches the latest build, swaps it in and restores the old one if the new one fails to start. 'version shows the version, build number, commit, release tag, channel and build date — 'version --copy puts it on your clipboard for a bug report.
Can I bring my setup with me?
Your shell profile works as-is. On top of that, ~/.oxis/config.lua runs at startup, themes are JSON files in ~/.oxis/themes/, each project can carry a .oxis/workspace.lua, and 'backup / 'restore move everything between machines.
What about macOS?
There's a preview for Apple silicon: OXIS.app in the latest build. Every change is built and tested on macOS, but nobody has used it on a Mac yet, so issues and pull requests are very welcome. It isn't signed: right-click → Open the first time.
